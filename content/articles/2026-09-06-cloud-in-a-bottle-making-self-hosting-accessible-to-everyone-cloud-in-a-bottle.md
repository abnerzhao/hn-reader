## easy

Cloud in a Bottle is a personal cloud you can run yourself. It hosts apps in secure containers. This means you can use existing software with very few changes.

The main idea is simple. Today's web apps are often owned by big companies. They track you and show ads. Cloud in a Bottle gives you a private, safe space online. It works like your own smartphone for web apps.

You get one login for all your apps. Apps can also share data with your permission. The software is free and open source. It has no tracking. You can start using it for free or set it up yourself.

## medium

The modern digital landscape often feels misaligned with our own interests. The software we rely on is frequently designed to be addictive, loaded with advertisements, and focused on tracking users to sell their data. While creating software has never been easier, a major shift has occurred: software is now predominantly served from the cloud. This model offers a fantastic user experience—no installation, access from any device, and easy collaboration—but it comes with significant costs. These costs are typically borne by a company behind the software, creating a financial incentive that is fundamentally at odds with the user's well-being.

In the past, open-source software thrived because users hosted it on their own computers. Today, cloud-based software is centralized, with a single instance serving everyone, and open-source creators cannot afford to bear those hosting costs. While self-hosting solutions exist, they are often seen as niche and intimidating. Existing platforms have their own drawbacks: some are abandoned or require major software alterations, others are slow and enterprise-focused, and many lack proper security isolation between applications. Another option allows for containerized apps but treats each one as an isolated island with its own separate login.

To address these challenges, a new project called Cloud in a Bottle was created. At its core, it is an Ubuntu machine with a web server that hosts a dashboard and routes requests to containerized applications. These apps run in secure, isolated containers, meaning existing software can be used with minimal changes. Unlike simpler hosting tools, Cloud in a Bottle offers platform features that apps can optionally use to create a much more integrated experience. The goal is to make self-hosting feel like owning a personal 'cloud smartphone' where finding and installing great apps is effortless.

A key feature is that once you are logged into your Cloud in a Bottle instance, you are automatically authenticated across all your apps, eliminating the need for separate accounts everywhere. The platform also provides an interface for apps to securely share data and capabilities with each other, similar to how smartphone operating systems manage permissions for sensors or health data. The project is open-source, self-hostable, and contains zero telemetry. While a managed version is offered to make it widely accessible and support development, the open-source path uses the exact same code and remains a first-class option.

After over six months of private development, the platform is now launching. The creator has been migrating their own digital life to their personal Bottle instance with great satisfaction. A primary goal is to help catalyze the creation of more high-quality open-source web software suitable for everyone, not just technical enthusiasts. The curated app catalog is currently small but growing weekly. For now, early adopters may need some technical familiarity, but the long-term vision is for the experience to become seamlessly accessible to all users.

## hard

I find myself increasingly frustrated with the state of the digital world, where the software we rely on is deliberately engineered to be addictive, saturated with advertisements, incessantly tracking our behaviour and monetising our data, all while continually deteriorating in quality. Despite the fact that creating software has never been easier, we have arrived at a situation where the incentives of providers are fundamentally opposed to those of users. I believe a major contributor to this dilemma is the migration of applications to the cloud, a shift that has re‑distributed both the benefits and the burdens of software delivery.

When a program is served from the cloud—think of Google Docs versus a locally installed copy of Microsoft Word—the user enjoys a seamless experience: no installation required, access from any device, and instant sharing or collaboration. Yet delivering a service in the cloud incurs real costs, and consequently almost every modern web offering is backed by a commercial entity that must recoup those expenses. Open‑source developers, who wish to give their work away for free, are naturally reluctant to shoulder the financial burden of hosting their software for a global audience, and the companies that do step in are driven by profit motives that often clash with the privacy‑preserving, user‑centric values of the community.

In the era before ubiquitous cloud hosting, the open‑source model worked differently: authors distributed their binaries and each individual effectively became the host, running the program on their own personal computer. Today, however, cloud software tends to be centralized, with a single instance serving millions while the creator absorbs the operational expenses. This centralisation persists because most people lack a straightforward way to place software into the cloud for themselves; self‑hosting solutions exist, but they remain niche and intimidating for the average user.

When I surveyed the landscape of existing self‑hosting platforms, none felt adequate. Sandstorm.io, although philosophically aligned with my vision and even echoing the arguments I now make in a 2014 article, has long been abandoned and demands substantial modifications to existing applications to run on its framework. NextCloud has grown sluggish and unreliable, shifting its focus toward enterprise deployments. Yunohost executes apps directly on the host without sandboxing, meaning a vulnerability in one program can compromise the entire server. Coolify, while capable of containerising applications, treats each app as an isolated island with its own login mechanism and little integration with the host or with other services.

Cloud in a Bottle emerged as another attempt to reconcile these shortcomings. At its foundation it is simply an Ubuntu machine equipped with a web server that presents a dashboard and routes HTTP(S) traffic to a collection of containerised applications. Those containers are run rootless and hardened, providing a reasonably secure sandbox that allows existing software to be executed with minimal alterations. Beyond mere container hosting, the platform offers a suite of opt‑in features that apps may adopt to enrich the user experience, such as unified single‑sign‑on and a mediated interface for granting permissioned access to data and capabilities between different applications.

I envision the system behaving like a personal “cloud smartphone”: a device you own, where discovering and installing high‑quality apps is trivial, and where the overall interaction feels as polished as the proprietary products we seek to replace. To achieve this, we have devoted considerable effort to designing the personal‑cloud analogue of the APIs that mobile operating systems expose—think sensor access, push notifications, health‑data sharing, and similar services—so that apps can integrate smoothly and deliver a cohesive experience. The project is released as open source, incorporates no telemetry, and strives to be as straightforward and “magic‑free” as possible.

Although we also provide a managed hosted version (which supplies a simple business model to sustain development), the open‑source, self‑hosted distribution runs exactly the same code and retains first‑class status. After more than six months of private testing, during which the core platform attained stability, we are now launching publicly. I have already migrated a significant portion of my own digital life into a Bottle instance, and the results have been gratifying. Nevertheless, a chicken‑and‑egg dilemma remains: without an accessible means for individuals to self‑host open‑source web software, the audience for such tools stays small, and the catalogue of available applications stays limited. To address this, we are curating an app selection that upholds a high bar for user experience, adding new titles each week and hoping to accelerate growth with community contributions. Early adopters may still need a modicum of technical comfort—or the assistance of a coding agent—to locate, create, or adapt the software they wish to run, but the process is deliberately straightforward. As the catalogue deepens and the interface continues to be refined, we anticipate that the solution will become approachable for everyone. Those interested can try a managed instance with a complimentary $10 credit, deploy on a cloud VPS, install on personal hardware (whether in a virtual machine or on bare metal), inspect the source on GitHub, or join the conversation on Matrix.
