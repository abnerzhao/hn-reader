## medium

Day to day I think a surprising amount of engineering productivity comes from small nuggets of knowledge: being aware that a language feature exists, knowing that an unexplained TCP delay is probably related to the TCP_NO_DELAY setting and Nagle’s algorithm, or remembering the right git incantation to get out of a pickle. Even a simple trick like using python3 -m http.server to start a quick server in a directory can make work a bit easier, even if you don’t know much Python.

You probably know that Ctrl + r lets you search your terminal’s command history, but installing fzf turns that into a fuzzy search. If you want more power, atuin replaces your shell history with a searchable SQLite database, and per-directory-history lets you switch between searching commands from a specific directory or from all previous commands. You can also decide how much history to keep. In SQL you can SELECT without a FROM clause, which is handy for testing how a function behaves or reminding yourself how SELECT TRUE <> NULL works. Both PostgresSQL and MySQL support EXPLAIN ANALYZE, which runs the query and gives detailed performance information.

In regular expressions the word‑boundary assertion — b — makes it easy to match the beginnings or ends of words. You can use logarithms to bucket metric values, for example const bucket = Math.floor(Math.log10(userInGroupCount)) and then increment a metric with that bucket. Modern JavaScript now offers Array.flatMap, Object.entries, and Promise.withResolvers. In Node.js you can keep a connection open to an external resource by creating an https.Agent and passing it to your HTTP calls, which can dramatically reduce latency.

Git has a handy pickaxe option: git log -S pattern finds all commits that added or removed a given string, and git log -G pattern also shows when a line was moved. Similar to cd -, you can use git checkout - to switch back to your previous HEAD. Many find commands can be replaced with globs like **/*.md; most shells support this out of the box, but in Bash you need shopt -s globstar. Most people prefer rg (ripgrep) over grep, ack, or ag, and Zsh’s advanced autocompletion isn’t on by default—you can enable it with a few lines that add the brew‑share path and run compinit.

I’ve found that sharing one small trick each day with an engineering team works well; even if people already know nine out of ten tips, the tenth often saves time and can spark useful discussion. At a company I think of knowledge as a collection of high‑leverage nuggets: to debug a problem use a certain data source, ask a person who knows a lot about an area, consult good docs for a hard thing, manually scale out when a signal appears, run a specific command for a rolling restart, or use a utility that makes a problem easy to script. If you’re a senior engineer, consider doing something similar—it’s a habit I first saw on Julia Evans’s blog, where she puts it perfectly: “small bits of knowledge are powerful! and fun! and approachable!!”

## hard

Day to day, I think a surprising amount of engineering productivity comes from small nuggets of knowledge: being aware that a language feature exists; knowing that an unexplained TCP delay is probably related to the TCP_NO_DELAY setting and Nagle’s algorithm; knowing the right git incantation to get out of a pickle; or knowing a trick with sed to rewrite a file. In one sense, this is self-evident: anything you know is made up of smaller pieces of knowledge, and those pieces matter. Yet some nuggets are especially valuable because they require little supporting mental infrastructure. You do not need to know any Python to run python3 -m http.server and start a simple server in a directory, but the command may still make your work marginally easier.

You probably know that ctrl + r searches your terminal’s command history, but installing fzf allows you to configure it to perform a fuzzy search instead. For even more power, atuin replaces your shell history with a searchable SQLite database. per-directory-history lets you switch between searching commands run in the current directory and searching your entire command history. You can also configure how much history is retained. In databases, SQL permits SELECT statements without a FROM clause. This can be useful for testing how a database function actually behaves or reminding yourself how SELECT TRUE <> NULL works. Both PostgreSQL and MySQL support EXPLAIN ANALYZE, which executes the query under investigation and provides substantially more information about its performance.

In regular expressions, the word-boundary assertion, written as `b`, makes it straightforward to find the beginnings or ends of words. Logarithms can also help when working with metrics. For example, you can bucket a value by its order of magnitude: const bucket = Math.floor(Math.log10(userInGroupCount)); metrics.increment('my_metric', { bucket }); Modern JavaScript now includes Array.flatMap, Object.entries, and Promise.withResolvers. In Node.js, an https.Agent can keep a connection open to an external resource and make subsequent HTTP requests more efficient: fetch(url, { method, agent }). Reusing those connections can have a dramatic impact on latency.

The git command git log -S pattern, sometimes called pickaxe, identifies every commit that added or removed a particular string in a codebase. It is remarkably useful, especially with older codebases. git log -G pattern is similar, although it also reports commits in which that line was moved. Like cd -, git checkout - lets you return to your previous HEAD. You probably do not need find for many everyday tasks, since globs such as **/*.md can replace a large number of find commands. Most shells support this syntax out of the box, but Bash requires shopt -s globstar. In a similar vein, most people will probably prefer rg, also known as ripgrep, to grep, ack, or ag.

Zsh’s advanced autocompletion features are not enabled by default. The following configuration loads the functions provided by Homebrew and initializes completion: if type brew &>/dev/null; then FPATH='$(brew --prefix)/share/zsh/site-functions:${FPATH}' fi; autoload -Uz compinit; compinit. You may already have known all of these tricks, or you may work in a domain in which they are completely useless. Even if this particular collection does not help you, you probably have your own stash of techniques accumulated over the years, each one making some part of your work easier.

At a company, even more knowledge tends to take this form: small nuggets with high leverage. To debug $PROBLEM, use $DATA_SOURCE. $PERSON knows an enormous amount about $AREA and will usually help if you get stuck. Good documentation exists about $HARD_THING at $OVER_HERE. When $THING happens, the expected response is to scale out manually. To perform a rolling restart of a service, run $THIS_COMMAND. This particular utility makes $THAT_PROBLEM easy to script. These pieces of knowledge are valuable because they remove hesitation and turn unfamiliar problems into familiar procedures.

At a previous company, I shared one trick with the engineering team every day on Slack, including both general technical advice and company-specific knowledge. People found the posts quite useful. Even if they already knew nine out of ten tricks, the tenth document or technique might save them time. One trick per day was the right quantity: enough to help without overwhelming people, and occasionally enough to spark a useful discussion. If you are a more senior engineer at your company, you might consider doing something similar. I first encountered this technique on a blog by Julia Evans, whose writing often captures the idea behind it perfectly: small bits of knowledge are powerful! and fun! and approachable!!
