## easy

MCP 2. 0 is a new way to connect tools to AI programs. It replaced an older system that was complex. Now, tools talk in one step, not two. This makes it easier to build and use. I built three tools this week to test it. The change also makes servers need less memory. Less memory is good for phones or laptops. MCP still helps AI use tools safely, unlike typing commands directly. Hackers find it harder to break.

I made a tool called mcp-explorer. It checks MCP servers with simple commands. You type: uvx mcp-explorer list [link]. It shows tools like showing SVG images or running JavaScript.

## medium

The Model Context Protocol (MCP) introduced by Anthropic in late 2024 experienced a resurgence in 2026 with the release of MCP 2.0, also called the 2026-07-28 specification. This update marked the most substantial change to the protocol since its launch. It simplified implementations by eliminating session-based interactions, replacing them with a single HTTP request structure. Legacy MCP required two steps to call a tool: initializing a session and then invoking the tool. The new version consolidates these into one request, specifying the method, tool name, and parameters directly. This reduces server-side complexity, especially for scalable applications that avoid state management. The shift also lowers hardware demands, making it feasible for smaller tools to run on local devices.

The difference between stateful and stateless MCP became clearer through examples. In legacy MCP, a client first requests a session identifier and then uses it in subsequent tool calls. The updated spec, however, bundles all necessary data—like the tool name, arguments, and client metadata—into one message. This streamlines both client and server code. For instance, a search query in stateless MCP includes the tool name, parameters, and client details in a single JSON object, without needing prior session setup. Tools like mcp-explorer demonstrated this approach by handling interactions via CLI. Built with Python and designed to work with uvx, this tool lets users list, inspect, and call MCP tools from an MCP server with simple commands. Testing it against a demo MCP endpoint showed it could query available functions, examine their input/output schemas, and execute actions like rendering Mermaid diagrams.

mcp-explorer serves as a practical tool for exploring MCP specifications. It eliminates the need for external installations by leveraging uvx, a package runner compatible with modern JavaScript environments. Users can interact with an MCP server by passing its URL, then use commands to list tools, inspect their definitions, or trigger actions. For example, calling a Mermaid rendering tool involves specifying the source code and options, returning SVG or text outputs. This hands-on approach helps developers understand MCP’s structure and capabilities. The tool’s stateless design aligns with the new protocol, ensuring no lingering session states. A README file included additional commands, but the core functionality revolved around inspecting tools and executing predefined operations with minimal setup.

datasette-mcp is a plugin extending Datasette’s capabilities to interact with MCP. It adds an endpoint to any Datasette instance, allowing agents or AI chat tools to send MCP requests to query or modify database data. Initially challenging due to the protocol’s earlier complexities, the new stateless version simplified integration. The plugin implements three tools: listing databases, retrieving schema details, and executing read-only SQL queries. These functions enable an AI agent to perform structured database operations without raw shell access. Deploying it on a public demo instance, such as datasette.simonwillison.net, made it accessible to external tools. By using ChatGPT or Claude with this endpoint, users could trigger SQL queries indirectly through natural language prompts. The plugin’s success hinged on aligning with stateless MCP’s simplified request format, ensuring cleaner interactions between the database and the agent.

The security advantages of MCP became a key focus after earlier concerns about prompt injection vulnerabilities. Initially, critics argued that MCP shifted security burdens to users by allowing arbitrary tool combinations. This risk increased with general agents using unrestricted terminal and curl access. MCP’s structured approach, however, constrains how tools can be chained, making it easier to audit permissions and prevent misuse. For example, a Datasette plugin that only allows SQL queries over specific databases inherently limits actions compared to giving full terminal access. Similarly, mcp-explorer’s CLI tools restrict operations to predefined MCP functions, reducing unintended behavior. Developers working on sensitive applications, like personal blogs or private data systems, find MCP’s explicit design reduces exposure to unintended risks compared to open-ended tool ecosystems.

Ongoing projects highlight MCP’s growing utility. An llm-mcp-client tool recently emerged, offering an official integration for LLM-based applications. This plugin connects models to MCP servers, enabling natural language prompts to trigger database queries or other MCP actions. Testing it with a Datasette instance showed that an LLM could interpret ambiguous requests, like 'count the notes,' by querying both published and draft notes before providing a total. The tool’s early integration into LLM systems suggests that MCP could become a standard interface for AI-driven workflows. Future versions might embed MCP directly into LLM cores, further streamlining agent development. The stateless design remains central to these advancements, ensuring compatibility across new and existing tools while maintaining security and simplicity.

## hard

Tuesday, July 31st, 2026, marked the advent of Stateless MCP, characterized by the rollout of the MCP 2.0 specification—formally designated as the 2026-07-28 Model Context Protocol specification. This represents the most profound evolution of the MCP standard since its inception, serving to reignite a personal fascination with the protocol. Originally introduced by Anthropic in November 2024, MCP provides a standardized mechanism for exposing new tools to LLM-powered agent frameworks. While the protocol saw a massive surge of interest throughout 2025, it was momentarily eclipsed by Skills, an alternative Anthropic invention based on the premise that an agent harness equipped with a terminal and curl could achieve most MCP functionalities with greater flexibility. However, the return to MCP is driven by necessity; providing an agent with a shell environment and internet access introduces significant risks and demands a highly capable model. In contrast, MCP tools are easier to audit and control, remaining simple enough for smaller, locally running models to operate effectively.

The transition to a stateless specification drastically simplifies the implementation of both clients and servers. To understand the distinction, one must examine the differences between the legacy stateful MCP and the new stateless methodology. The legacy version required a two-step interaction: an initial HTTP request to initialize a session and obtain a Mcp-Session-Id, followed by a second request to actually call the tool via a POST request containing that session ID. This approach necessitated server-side state management to track session IDs and complicated routing within distributed backend systems. The new stateless approach, however, achieves the same goal with a single HTTP request. By incorporating the protocol version, method, and tool name directly into the headers, the implementation becomes significantly cleaner. This architectural shift makes the protocol far more suitable for building scalable web applications, as it removes the burden of maintaining session state on the server side.

The newfound simplicity of the protocol inspired the creation of mcp-explorer, a stateless Python CLI tool designed for the interactive probing of MCP servers. Because it is stateless, it can be run via uvx without requiring a formal installation. For example, using 'uvx mcp-explorer list' against a remote endpoint can retrieve a comprehensive list of available tools, such as those used to execute Mermaid SDK code or render diagrams as SVG or PNG. The tool allows for deep inspection; 'uvx mcp-explorer inspect' can reveal the full JSON schema for inputs and outputs, while the 'call' command allows users to execute specific tools with designated arguments. This process of building a CLI tool serves as an effective method for mastering the intricacies of a new specification, even when a significant portion of the code is generated by an agent.

Another significant development is datasette-mcp, a Datasette plugin that introduces a /-/mcp endpoint to any instance. After several failed attempts at building this plugin, the stateless specification finally provided a framework that felt ready for release. It provides three core tools: list_databases(), get_database_schema(), and execute_sql(). The latter is currently restricted to read-only operations. When integrated with agents or chat interfaces like ChatGPT and Claude, these tools allow the models to run SQL queries against a hosted Datasette instance. Practical testing on a blog mirror demonstrates the utility; for instance, an agent can successfully navigate complex queries, such as determining recent posts by an author, by executing multiple sequential SQL queries to extract the necessary information.

Further extending this utility is the llm-mcp-client, an alpha plugin for the LLM tool designed to provide official MCP integration. This plugin allows for seamless interaction between the LLM and an MCP-enabled endpoint, such as the Datasette mirror. When prompted to perform a task—like counting specific entries—the LLM can reason through the ambiguity of the request, decide on the necessary queries to ensure accuracy, and execute them to produce a verified count. The success of this integration suggests a future where such capabilities are brought directly into the LLM core, alongside potential experiments in Datasette Agent and llm-coding-agent.

Ultimately, the move toward MCP is motivated by security concerns. Earlier observations suggested that patterns involving the mixing of tools often shifted the burden of avoiding data exfiltration attacks onto the end user. This vulnerability is exacerbated when general agents are granted arbitrary shell and curl access, a scenario that is incredibly difficult to secure. MCP provides a much more manageable way to reason about agent capabilities and potential failure modes compared to open network command execution. Consequently, MCP is becoming a preferred choice for developing sensitive applications that rely on large language models, offering a safer alternative to the risks inherent in unrestricted agent environments.
